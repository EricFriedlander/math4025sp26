Today

We’ll cover some common pre-processing tasks provided by scikit-learn:

  • Standardization (e.g. centering and scaling)
  • Non-linear transformations (e.g. Box-Cox, Yeo-Johnson)
  • Normalization (scaling observations)
  • Encoding categorical variables
  • Generating polynomial features & discretization
  • Custom transformations & feature selection

Reminder: Pipelines & ColumnTransformers

We use Pipelines and ColumnTransformers to bundle preprocessing and modeling steps, preventing data leakage and keeping our code organized.

  • Pipeline: Chains together a sequence of steps (like transformers) optionally ending with an estimator. Data flows sequentially through each step.
    • When to use: When you want to apply a sequence of transformations to the same variables in order.
  • ColumnTransformer: Applies different transformers (or pipelines) to different columns of an array or DataFrame.
    • When to use: When you have mixed data types (e.g., numeric vs. categorical) needing different preprocessing steps before being combined back together.

Pipelines & Cross-Validation

  • When using pipelines with cross-validation, the pipeline is fit on the analysis set in each iteration, and then used to transform the assessment set for that iteration
  • This prevents data leakage from the assessment set into the analysis set

When is pre-processing part of the model?

  • Some pre-processing is done before we split our data
    • Idea: these steps shouldn’t be impacted by patterns in training data (e.g. removing ID variables, renaming categories, etc.)
  • Some pre-processing is done after we split our data
    • Idea: these steps should be impacted by patterns in training data (e.g. scaling, imputing missing values)
    • Think of these as part of the model

Pre-Split Cleaning

  • Before you split your data: make sure data is in correct format
  • This may mean different things for different data sets
  • Common examples:
    • Fixing names of columns
    • Ensure all variable types are correct (programming language dependent)
    • Ensure all categorical variables are correct and in order (if applicable)
    • Remove any variables that are not important (or harmful) to your analysis (e.g. ID variables, variables that your model shouldn’t “see”)
    • Ensure missing values are coded as such (i.e. as NaN instead of 0 or -1 or “missing”)
    • Fill in missing values where you know what the answer should be (i.e. if a missing value really means 0 instead of missing)

Post-Split Cleaning

  • Many pre-processing steps should be thought of as part of your model
  • Think: will the result of this step change based on my training data?
  • Examples:
    • Scaling: mean and sd are computed from training data
    • Imputing missing values: missing values are imputed using the training data
  • Some steps can be part of your model in certain cases but not in others:
    • One-Hot-Encoding: if you want to keep all categories, this can be done before splitting (but may cause issues if a category is only present in an assessment set)
    • Removing variables: if you know a variable is not important, you can remove it before splitting (are you removing the variable due to patterns in the training data or subject matter expertise?)
    • Lumping rare categories: are you lumping the categories due to patterns in the training data or subject matter expertise?
  • Idea: think of CV as a way of evaluting your process more than just a single model fit

Standardization

  • What it does: Standardizes features by to put them on the same scale, or scaling features to a specific range.
  • Functions:
    • StandardScaler: Centers and scales features to have a mean of 0 and variance of 1.
    • MinMaxScaler: Scales features to lie between a given minimum and maximum value (often between zero and one`). Robust to very small standard deviations and preserves zero entries in sparse data.
    • MaxAbsScaler: Scales each feature by its maximum absolute value. Meant for data that is already centered at zero or sparse data.
    • RobustScaler: Uses robust statistics (e.g., median and interquartile range) to scale features in the presence of outliers.

Non-linear Transformation

  • What it does: Maps features to a different distribution to stabilize variance and minimize skewness.
  • Functions:
    • QuantileTransformer: Maps the data to a uniform or normal distribution using quantile information. Smooths out unusual distributions and is less influenced by outliers, but distorts correlations and distances within and across features.
    • PowerTransformer: Applies monotonic transformations (Yeo-Johnson or Box-Cox) to map data as close to a Gaussian distribution as possible. Useful for stabilizing variance and minimizing skewness.

Box-Cox Transformation

  • Available via PowerTransformer(method='box-cox').
  • Attempts to make data more “normal” (Gaussian-like) by learning a parameter \(\lambda\).
  • Restriction: Can only be applied to strictly positive data (\(x_i > 0\)).
  • Formula: \[ x_i^{(\lambda)} = \begin{cases} \frac{x_i^\lambda - 1}{\lambda} & \text{if } \lambda \neq 0, \\ \ln(x_i) & \text{if } \lambda = 0. \end{cases} \]

Yeo-Johnson Transformation

  • Available via PowerTransformer(method='yeo-johnson').
  • A more robust extension of Box-Cox that works with positive, negative, and zero values.
  • Formula: \[ x_i^{(\lambda)} = \begin{cases} \frac{(x_i + 1)^\lambda - 1}{\lambda} & \text{if } \lambda \neq 0, x_i \ge 0 \\ \ln(x_i + 1) & \text{if } \lambda = 0, x_i \ge 0 \\ -\frac{(-x_i + 1)^{2 - \lambda} - 1}{2 - \lambda} & \text{if } \lambda \neq 2, x_i < 0 \\ -\ln(-x_i + 1) & \text{if } \lambda = 2, x_i < 0 \end{cases} \]

Normalization

  • What it does: Scales individual observations (rows), rather than features (columns), so that they have a length (norm) of 1.
  • Intuition: Changes the magnitude of an observation without changing its direction in space.
  • Example Use-Case: Text classification. If Document A is just a longer version of Document B (same relative word frequencies, just more words), normalizing them ensures they look identical to your model.
  • Functions:
    • Normalizer: Scales individual samples to have a unit l1, l2, or max norm. Frequently used before clustering or calculating similarities between samples (like cosine similarity).

Encoding Categorical Features

  • What it does: Converts categorical text data into numeric formats that machine learning algorithms can process. Also includes handling rare categories.
  • Functions:
    • OneHotEncoder: Creates dummy variables (one-hot encoding).
    • OrdinalEncoder: Assigns integer values to ordinal categories.
    • TargetEncoder: Supervised encoding based on the target variable.
    • RareLabelEncoder: Groups infrequent categories into a single label (from feature_engine package).

Discretization

  • What it does: Partitions continuous features into discrete intervals or bins (also called quantization or binning).
  • Functions: KBinsDiscretizer, Binarizer.

Generating Polynomial Features

  • What it does: Creates new features by generating polynomial and interaction terms, or generates B-spline basis functions for splines. This allows linear models to capture non-linear relationships.
  • Functions: PolynomialFeatures, SplineTransformer.

Custom Transformers & Feature Selection

  • What it does: Applies user-defined functions to the data, or removes features based on specific criteria like lack of variability.
  • Functions:
    • FunctionTransformer: Wraps a custom Python function to be used in a pipeline.
    • VarianceThreshold: Removes features whose variance doesn’t meet a specified threshold (e.g., zero or near-zero variance features).

Order of Preprocessing Step

Questions to ask:

  1. Should this be done before or after data splitting?
  2. If I do step_A first what is the impact on step_B? For example, do you want to encode categorical variables before or after normalizing?
  3. What data format is required by the model I’m fitting and how will my model react to these changes?
  4. Is this step part of my “model”? I.e. is this a decision I’m making based on the data or based on subject matter expertise?
  5. Do I have access to my test predictors?

Questions

  • Should I lump before or after dummy coding?
  • Should I dummy code before or after normalizing?
  • Should I lump before my initial split?
  • How does ordinal encoding impact linear regression vs. KNN?

Recap

  • Preprocessing Needs: Prevent information leakage by exclusively using training data parameters.
  • scikit-learn Pipeline: Crucial for bundling preprocessing steps with the estimator to prevent data leakage.
  • Common Tasks:
    • Standardization: StandardScaler, MinMaxScaler, RobustScaler.
    • Non-linear Transformation: QuantileTransformer, PowerTransformer (Box-Cox, Yeo-Johnson).
    • Normalization: Normalizer (scales individual observations to unit norm).
    • Categorical Encoding: OneHotEncoder (dummies), OrdinalEncoder, RareLabelEncoder.
    • Discretization: KBinsDiscretizer, Binarizer.
    • Polynomial Features: PolynomialFeatures, SplineTransformer.
    • Custom/Feature Selection: FunctionTransformer, VarianceThreshold.
  • Order matters!: Be mindful of when to apply scaling vs. dummy-ing or imputation.
