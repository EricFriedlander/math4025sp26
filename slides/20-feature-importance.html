Why Feature Importance?

Interpretability vs. Accuracy

  • Ensemble models (bagging, random forests) achieve high accuracy but are hard to interpret directly
  • Feature importance gives us a window into black-box models:
    • Which inputs actually drive predictions?
    • Which can be safely ignored?
  • Useful for: model debugging, communication with stakeholders, feature selection, detecting data leakage

Two Approaches

MDI: Mean Decrease in Impurity

How MDI Works

At every split in every tree:

  1. A feature is chosen and a threshold is selected to split a node
  2. The decrease in impurity (SSE or Gini or entropy) caused by that split is recorded for the chosen feature
  3. After fitting all trees, sum the total impurity decrease attributed to each feature across all splits and all trees

The result is a score per feature: higher = more useful for splitting.

MDI: Pros and Cons

Pros:

  • Computed for free during training - no extra computation needed
  • Available directly as feature_importances_ on any sklearn tree-based model
  • Fast even with many features

Cons:

  • Only works for tree-based models
  • Biased toward high-cardinality features: a feature with many unique values (or many one-hot encoded levels) has more split opportunities and tends to get inflated importance (can mitigate by limits tree depth)
  • Evaluated on training data: can overstate importance of features the model overfits to

Permutation Importance

How Permutation Importance Works

For each feature \(j\):

  1. Compute baseline accuracy on the test set (no shuffling)
  2. Randomly shuffle feature \(j\)’s values in the test set, breaking its relationship with the response
  3. Re-score the model on the shuffled data and record the drop in accuracy
  4. Repeat \(k\) times (e.g., 10) and average the drops

A large drop means the model relied heavily on that feature. Near-zero or negative drops indicate the feature was not contributing.

Permutation Importance: Pros and Cons

Pros:

  • Model-agnostic: works with any fitted model (logistic regression, SVMs, neural nets, etc.)
  • Evaluated on the test set: reflects real generalization performance
  • Provides uncertainty estimates (std dev across repeats)

Cons:

  • Slower: requires \(k \times p\) forward passes through the model
  • Correlated features can share importance: shuffling one correlated feature may not drop accuracy much if the other correlated feature is still intact
  • Results depend on the random shuffling seed

MDI vs. Permutation: Which to Trust?

  • When they agree: strong evidence a feature matters
  • When MDI is high but permutation is low:
    • The feature may have been overfit (more splits on training data don’t help test performance)
    • Or it’s a high-cardinality feature benefiting from MDI’s bias
  • When permutation is high but MDI is low:
    • Less common - usually MDI and permutation agree on truly important features
  • General advice: prefer permutation importance for final reporting; use MDI for quick exploration

Recap

Feature Importance: Key Ideas

MDI (Mean Decrease in Impurity)

  • Built into tree-based models - free, fast, available as feature_importances_
  • Computed on training data: can overstate importance for overfit features
  • Biased toward high-cardinality features (many one-hot levels get more split opportunities)
  • Best for: quick exploration during model development

Permutation Importance

  • Model-agnostic: works with any fitted model
  • Evaluated on the test set: reflects real generalization
  • Shuffle one feature, measure accuracy drop - repeat and average
  • Best for: final reporting, comparing importance across different model types

Big Picture

  • When MDI and permutation importance agree, you can trust the result
  • When they disagree, prefer permutation importance - it uses held-out data
  • Features that rank highly across multiple model families (trees, linear models) are the most reliable signals
