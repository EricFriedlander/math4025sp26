Data Wrangling Tips

StarFormation Project — Math 4025

Overview of the Data

Your project data spans 8 files. The table below summarizes what each one contains and how it connects to the others.

File Format ~Rows Join Key Contents
MRT-phot.txt Fixed-width 6,176 YB Spitzer photometry (8–70 µm), errors, counts, quality flags
MRT-dist.txt Fixed-width 6,176 YB Distances with uncertainties
MRT-velo.txt Fixed-width 6,176 YB Radial velocities (km/s)
MRT-xmat.txt Fixed-width 6,176 YB Cross-matches to external catalogs
MRT-hcsc.txt Fixed-width 3,945 YB Herschel-derived properties (subset)
MIRION_meta_all_1.csv CSV 3,945 YB All 8 target physical properties
MIRION_meta_din_1.csv CSV 3,945 YB Distance-independent subset of targets
MIRION_spec_1.csv CSV (transposed) 10 wavelengths YB columns Long-wave photometry (160–1100 µm)

Key insight: Only ~3,945 YBs have physical property targets (the MIRION subset of the full 6,176). An inner join on YB will give you ~3,945 rows — this is your working modeling dataset.

Recommended starting point: MRT-phot.txt + MIRION_meta_all_1.csv. The other files add complexity and are worth exploring once you have a baseline model working.

Loading MRT Fixed-Width Files

The MRT files use a fixed-width format with a 38-line header. Use pd.read_fwf with explicit column specifications derived from the byte-by-byte description in each file’s header.

MRT-phot.txt

This is the primary feature table. The column specs below come from the byte-by-byte table in the header (subtract 1 from the start byte for 0-based indexing).

import pandas as pd
import numpy as np
from pyhere import here

phot_colspecs = [
    (0, 4),    # YB
    (5, 14),   # GLON
    (15, 23),  # GLAT
    (24, 31),  # MWPR
    (60, 68),  # F8
    (69, 77),  # e_F8
    (78, 85),  # F12
    (86, 94),  # e_F12
    (95, 102), # F24
    (103, 110),# e_F24
    (111, 120),# F70
    (121, 130),# e_F70
    (131, 133),# N8
    (134, 136),# N12
    (137, 139),# N24
    (140, 141),# N70
    (142, 146),# f_SAT
    (147, 148),# f_MULTI
    (149, 153),# f_NOSRC
    (154, 158),# f_PCONF
    (159, 160),# f_CEXT
]
phot_colnames = [
    "YB", "GLON", "GLAT", "MWPR",
    "F8", "e_F8", "F12", "e_F12", "F24", "e_F24", "F70", "e_F70",
    "N8", "N12", "N24", "N70",
    "f_SAT", "f_MULTI", "f_NOSRC", "f_PCONF", "f_CEXT"
]

phot = pd.read_fwf(
    here("data", "MRT-phot.txt"),
    colspecs=phot_colspecs,
    names=phot_colnames,
    skiprows=38,
    encoding='utf-8-sig'
)
Note

Use F8, F12, F24, F70 as column names — not bare numbers like 8, 12. Bare numeric column names cause issues in many pandas and scikit-learn operations.

MRT-dist.txt

The same pattern applies for the distance file. Groups whose target is distance-dependent (DIAM, MASS, L_BOL) will need this file. Groups with distance-independent targets (LM, TEMP, LRATIO, T_BOL, SURF_DENS) can skip it for their main analysis.

dist_colspecs = [
    (0, 4),    # YB
    (5, 11),   # DIST (kpc)
    (12, 17),  # e_DIST
    # ... (read the full header for additional columns)
]
dist_colnames = ["YB", "DIST", "e_DIST"]

dist = pd.read_fwf(
    here("data", "MRT-dist.txt"),
    colspecs=dist_colspecs,
    names=dist_colnames,
    skiprows=38,
    encoding='utf-8-sig'
)

Loading MIRION CSV Files

meta = pd.read_csv(here("data", "MIRION_meta_all_1.csv"), encoding='utf-8-sig')
meta_din = pd.read_csv(here("data", "MIRION_meta_din_1.csv"), encoding='utf-8-sig')
Note

BOM character warning. These CSV files have a UTF-8 BOM marker. Without encoding='utf-8-sig', the first column name will appear as ﻿YB (with an invisible prefix character) instead of YB. This causes silent KeyError failures when you try to use the YB column. Always use encoding='utf-8-sig' when loading these files.

Transposing MIRION_spec_1.csv

This file has an unusual layout: the rows are wavelength bands (F8 through F1100) and the columns are YB IDs. You need to transpose it before use.

# Load the raw file — first column is WAVE (wavelength), rest are YB IDs
spec_raw = pd.read_csv(
    here("data", "MIRION_spec_1.csv"),
    index_col=0,       # WAVE column becomes the row index
    encoding='utf-8-sig'
)
# spec_raw shape: (10 wavelengths) × (3945 YBs)

# Transpose: rows become YBs, columns become wavelength bands
spec = spec_raw.T.copy()
spec.index.name = "YB"
spec.columns = ["F8", "F12", "F24", "F70", "F160", "F250", "F350", "F500", "F870", "F1100"]

# CRITICAL: convert the YB index to numeric before joining
spec.index = pd.to_numeric(spec.index)
Note

Numeric index conversion is critical. After transposing, the YB values in the index are strings (e.g., "6.0", "7.0"). The phot and meta tables have numeric YB values. If you join a string index to a numeric index, pandas produces an empty DataFrame with no error — a silent failure. pd.to_numeric() fixes this.

Joining Tables on YB

# Set YB as the index first
phot_indexed = phot.set_index("YB")
meta_indexed = meta.set_index("YB")

# Inner join: ~3,945 rows (only YBs with both photometry AND target properties)
df = phot_indexed.join(meta_indexed, how="inner")

To add supplementary tables:

dist_indexed = dist.set_index("YB")
df = phot_indexed.join(meta_indexed, how="inner").join(dist_indexed, how="left")

Use how="left" for supplementary tables (distance, velocity) so you don’t lose rows where those values are unavailable.

Why inner join for the main tables? An outer join would give 6,176 rows, but most would have NaN target values — useless for supervised learning. An inner join gives only the ~3,945 rows where both photometry and a target exist.

Handling Quality Flags

f_PCONF (Poor Photometric Confidence)

f_PCONF is a 4-character string where each character corresponds to a band (8, 12, 24, 70 µm, left to right). A "1" in a position means the photometry in that band has poor confidence and should not be trusted.

bands = ["F8", "F12", "F24", "F70"]
pconf = phot["f_PCONF"].fillna("0000").astype(str).str.strip().str.zfill(4)

for i, band in enumerate(bands):
    phot.loc[pconf.str[i] == "1", band] = np.nan

Apply the same approach for f_NOSRC (no source detected — the flux value is effectively noise).

Missing Value Sentinel (999)

Note

Some numeric columns in the MRT files use 999 or 999.0 as a placeholder for missing values. Replace these with NaN after loading:

df.replace(999, np.nan, inplace=True)
df.replace(999.0, np.nan, inplace=True)

Checking for Missing Values

Before modeling, understand your missingness pattern.

import missingno as msno
from itables import show

# Summary counts
show(df.isnull().sum().rename("missing").to_frame())

# Visual matrix — good for spotting patterns
msno.matrix(df)

F12 and F24 in particular have substantial missingness. Think carefully about whether to drop those rows or impute.

Key rule: never impute your target variable. Drop rows where your assigned target is NaN before any modeling.

df_clean = df.dropna(subset=["YOUR_TARGET"])  # replace with your actual target name

For feature missingness inside scikit-learn Pipelines, use SimpleImputer:

from sklearn.impute import SimpleImputer
imputer = SimpleImputer(strategy="median")

Log-Transforming Targets

Some target variables span many orders of magnitude. Before modeling, plot a histogram of your assigned target — if it is heavily skewed, a log transformation will usually improve model performance.

When reporting predictions, make sure to reverse any transformation you applied (e.g., np.exp() or 10**pred as appropriate).

Log-Ratio Features

The shape of an object’s spectral energy distribution (SED) — how bright it is at different wavelengths relative to each other — can be more informative than the raw fluxes. Log-ratios of flux bands capture this shape independently of total brightness.

# Example: log ratio of 70 µm to 24 µm (a warm dust indicator)
df["log_F70_F24"] = np.log10(df["F70"] / df["F24"])

If either flux is NaN or zero, the ratio will be NaN or infinite. Handle these downstream in your imputation step or filter them out beforehand.

Potential ratios to explore: F70/F24, F24/F12, F12/F8. With the long-wave bands from MIRION_spec_1.csv you can compute many more combinations.
